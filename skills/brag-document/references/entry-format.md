# Entry format

The bundle follows the Open Knowledge Format (OKF) v0.2: a folder of Markdown files with YAML frontmatter, one file per concept. Spec: https://github.com/GoogleCloudPlatform/open-knowledge-format. Use this exact structure, because `scripts/brag.py` parses it and Obsidian and Notion sync depend on stable field names.

## Bundle layout

```text
<bundle>/
├── index.md              # OKF root index; frontmatter is only okf_version
├── log.md                # generated by scripts/brag.py log; never edit by hand
├── .obsidian/app.json    # copied from assets/obsidian-app.json at setup
├── summaries/            # saved period summaries (optional)
├── views/                # interactive pages from scripts/brag.py viz; generated, safe to delete
└── 2026/
    └── 10/
        └── 2026-10-21-api-payments-migration.md
```

- Path: `YYYY/MM/YYYY-MM-DD-<slug>.md`, where the date is the entry's `date` and the slug is 2-6 key words of the title (drop short connectives like "de", "do", "the"), lowercase, hyphenated, ASCII only (drop accents).
- The path is the entry's OKF id, so never rename or move a file without updating links to it (editing.md covers this).
- If the slug already exists on that date, append `-2`.

## Entry schema

```markdown
---
type: brag-entry
title: Migração da API de pagamentos para v2
date: 2026-10-21
description: Liderei a migração da API de pagamentos para v2 sem downtime.
impact: Latência p95 caiu 40%; destravou a entrega do time de checkout.
tags: [projeto, lideranca]
status: stable
sources:
  - resource: https://example.atlassian.net/browse/PAY-123
    title: PAY-123 Migrar API v2
  - title: "E-mail: Obrigado pela migração"
    author: Ana Souza
    last_modified: 2026-10-22
---

Free notes, optional. Context that does not fit the fields: who was involved, trade-offs, what was learned.
```

Keep the fields in the order shown, so entries read the same in every editor.

| Field | Rule |
|---|---|
| `type` | Always `brag-entry`. OKF requires a non-empty `type`. |
| `title` | Short, outcome-first, in the person's language. |
| `date` | `YYYY-MM-DD`, when it happened (for multi-day work: when it shipped or finished). |
| `description` | One or two sentences: what the person did, with an active verb ("led", "built", "unblocked"). Required once `stable`; a draft may leave it out. |
| `impact` | Optional. Prefer a number; accept a plain sentence; leave out the key entirely when unknown. |
| `tags` | Flow list. Use the config's `tags`; free tags are allowed, lowercase, hyphenated. |
| `status` | `draft` if `impact` is missing or the person wants to come back to it; otherwise `stable`. |
| `sources` | Optional block list. Each item has `title`, plus `resource` (a URL) when one exists; for messages and meetings, `author` (the sender or organizer, left out when unknown) and `last_modified` (its date). Never quote message content. |

Quote any value that contains `: `, starts with `[`, `{`, `"` or `'`, or contains `#`. Use plain double quotes and no multi-line values; keep each field on one line.

## index.md

Write the body in the person's language; only the frontmatter is fixed.

```markdown
---
okf_version: "0.2"
---

# Brag document

Work log of <name>. One file per accomplishment, grouped by year and month. See [log.md](log.md) for the timeline.
```

## log.md

OKF's reserved changelog. `scripts/brag.py log <bundle>` rebuilds it from the entries: one `## YYYY-MM-DD` heading per date, newest first, one bullet per entry linking to it with a relative path. Without Python, write it by hand in that shape.

## Saved summaries

`summaries/YYYY-MM-DD-<slug>.md`, frontmatter `type: brag-summary`, `title`, `date`, `period: "2026-04-01..2026-09-30"`. The validator accepts them.

## Obsidian

Links are standard Markdown with relative paths, never `[[wikilinks]]`, because OKF readers do not resolve wikilinks. `assets/obsidian-app.json` sets Obsidian to create links in that form. If the bundle sits inside an existing vault, that vault's own settings win: tell the person to set *Settings → Files and links → Use [[Wikilinks]]* off and *New link format* to *Relative path to file*.
